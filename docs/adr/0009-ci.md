# 0009. Every pull request runs the syntax check and the tests

- Status: Accepted
- Date: 2026-10-26

## Context

CONTRIBUTING asked for `node --check` and `node --test` before a pull request, but nothing ran them. The documented syntax
check, `node --check a.js b.js c.js`, checked only the first file: `node --check` takes one script, and the rest become its
arguments.

## Decision

`.github/workflows/test.yml` runs on every pull request and on pushes to `main`:

1. a syntax check of every `.js` and `.mjs` in `app/`, `app/public/` and `app/tools/`, one file at a
   time, each `.js` as an ES module (`node --input-type=module --check`). Plain `node --check` reads a `.js` file here as
   CommonJS and passes an ES module with a syntax error;
2. `node --test app/test/*.test.mjs`.

It asks for `macos-14`, the runner name our CI host uses, with Node 22. It installs nothing (the repo has no
dependencies) and needs no org: the Apex sync tests read the Apex source. No step reads event data such as titles
or branch names, so nothing untrusted reaches a shell.

## Consequences

- Once Actions is on, a broken test or a syntax error shows on the pull request before review.
- As of 2026-10-26 it isn't. The repository has no workflow runs, and pull request #55, which added the workflow, showed
  only the credential scan. Until a repository admin turns Actions on (and a runner picks up `macos-14`), run the two steps
  yourself: CONTRIBUTING, Testing.
- The browser checks (keyboard walk, `a11y-audit.js`, the three themes) and in-org Apex validation stay manual. CLAUDE.md's
  Verifying changes lists them.

## Update, 2026-10-29

Before the public release, a separate CI service ran the tests instead: the unit tests with a coverage report, then the
browser tests in Chrome, and one pull request comment with the two results. Test files go in either step by their imports
(`app/tools/ci-test-files.mjs`), so any folder under `app/test` runs.

Both test steps supply coverage: Node writes `coverage/lcov.info`, and Chrome's execution counters are converted to
`coverage/ui.lcov` by `app/tools/browser-coverage.mjs`. A coverage service imports both reports. Inline scripts map back
to their HTML lines; appended test wrappers are excluded. The coverage converters are installed as CI tools in the
ignored `coverage/browser-tools` folder, outside the application. An empty browser coverage run fails the build.

## Update, 2026-11-02

The public repository runs `.github/workflows/test.yml` on GitHub Actions on every pull request.

## Update, 2026-11-09

The workflow runs on `ubuntu-24.04`, a standard GitHub-hosted runner. In the `salesforce` org, `macos-14` maps to a larger
runner the org doesn't offer, so the job was cancelled before its first step. Playwright installs Chromium with its system
libraries (`--with-deps`).
